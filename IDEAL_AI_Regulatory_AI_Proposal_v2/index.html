01 · PROBLEM DEFINITION

의료기기 제조사 RA 담당자와
규제 대응 전문가가 겪는 실제 문제

의료기기 제조사의 RA(Regulatory Affairs) 담당자와 규제 대응 전문가는 제품 개발 이후에도 방대한 규제 업무를 반복적으로 수행해야 합니다. 동일한 의료기기라도 등급·국가·사용목적에 따라 요구 문서와 기준이 달라지기 때문에, 단순 생성형 AI나 법규 검색 챗봇만으로는 실무를 대체하기 어렵습니다.

규정 탐색 비용

품목·등급·판매국가별 관련 법규와 가이드라인을 반복 확인해야 하며, 법규 개정 시 영향 범위를 수동으로 파악해야 합니다.

분산된 내부 Evidence

제품사양, 시험결과, IFU, 임상자료가 서로 다른 파일과 버전에 흩어져 있어 필요한 근거를 찾는 것 자체가 오래 걸립니다.

문서 간 불일치

동일 제품 정보가 여러 문서에 반복되면서 모델명·수치·버전 불일치가 발생하고, 검토에 상당한 시간이 소요됩니다.

검토 의존성

누락 여부와 규정 적합성이 숙련 담당자 경험에 의존하여, 담당자 교체 시 업무 연속성이 크게 떨어집니다.

자동화의 대상은 '문장 작성'만이 아니라
규정 판단 → Evidence 연결 → 문서 생성 → 검증의 전체 워크플로우입니다.

Target Workflow04
04 · DOCUMENT INTELLIGENCE

업로드된 문서를 단순 저장하지 않고
'AI가 활용 가능한 지식'으로 구조화합니다.

기업 내부자료는 항상 정리된 형태로 존재하지 않습니다. PDF, DOCX, XLSX, HWP/HWPX, 이미지 스캔 등 다양한 형식을 AI가 검색·활용할 수 있도록 변환하는 것이 워크플로우의 첫 번째 핵심 단계입니다.

STEP 01

Multi-format Parsing

PDF·DOCX·XLSX·HWP·이미지 스캔 문서에서 본문, 제목 구조, 표, 메타데이터를 추출합니다.

STEP 02

Semantic Segmentation

문서를 의미 단위로 분리하고 제품사양·시험·임상·위험 등 유형 태그를 부여합니다.

STEP 03

Entity Extraction

모델명, 사용목적, 성능수치, 시험결과 등 핵심 정보를 구조화된 데이터로 변환합니다.

STEP 04

Product Master

여러 문서에 흩어진 동일 제품 정보를 하나의 기준 데이터로 통합·연결합니다.

STEP 05

Evidence Indexing

원본 파일·페이지·Section을 보존한 채 검색 인덱스를 구축합니다.

STEP 06

Conflict Detection

문서 간 수치·표현이 상충할 경우 자동 확정하지 않고 검토 대상으로 분류합니다.

05 · SYSTEM ARCHITECTURE

의료기기 규제 업무에 맞는
Hybrid Regulatory AI Architecture

단일 LLM에 모든 판단을 맡기지 않습니다. Hallucination, 규정 누락, 잘못된 법규 적용을 방지하기 위해 네 개의 레이어가 역할을 분리합니다.

① Rule Engine
규제 판단
무엇을 지켜야 하는가?
제품군·품목·등급·사용목적·판매국가에 따라 적용 규정, 요구 문서, 필수 작성항목을 명시적으로 판정합니다. 동일 입력에 항상 동일한 결과를 보장하며, 법규 개정 시 Rule만 독립적으로 업데이트합니다.
② RAG Engine
근거 검색
어떤 근거가 있는가?
규제 Knowledge Base와 기업 내부자료에서 Semantic + Keyword + Metadata Filtering + Re-ranking으로 Section별 근거를 동시에 검색합니다. 검색 결과의 출처·버전은 생성 결과에 함께 보존됩니다.
③ LLM
문서 생성
어떻게 작성할 것인가?
Rule Engine이 결정한 요구사항과 RAG가 검색한 근거를 기반으로 승인된 문서 Template에 맞게 초안을 생성합니다. 근거가 없는 항목은 그럴듯하게 채우지 않고 REVIEW 상태로 표시합니다.
④ Validation
AI 검증
제대로 작성되었는가?
1차 생성 결과를 2차 AI가 다시 검토합니다. 필수항목 누락, 출처 없는 주장, 내부자료와 생성 내용 불일치, 문서 간 표현 충돌, 적용 규정 누락을 재검사하여 Human Review 전 품질을 확보합니다.

06 · EVIDENCE-FIRST GENERATION

AI가 왜 이렇게 작성했는지
근거까지 역추적할 수 있습니다.

생성된 문서의 주요 내용은 사용된 내부자료, 적용 규정, 해당 조항까지 연결됩니다. 전문가는 처음부터 다시 조사하는 것이 아니라 AI가 제시한 근거를 검증하는 방식으로 업무를 전환할 수 있습니다.

  • 생성 내용 → 사용 내부자료 → 적용 규정 → 해당 조항까지 추적
  • 근거 부족 항목은 [REVIEW] 상태로 분리 표시
  • AI 생성 / 사람 수정 / 최종 승인본 구분 기록
  • 출처 파일명·페이지까지 보존
  • 향후 수정 이력으로 기업별 작성 방식 개선 가능

08 · VALIDATION & HUMAN REVIEW

AI가 생성하고, AI가 다시 검증하고,
전문가가 최종 승인합니다.

AI Validation Layer

증거 기반 생성 결과를 2차 AI가 다시 검토합니다. 의료기기 규제 문서에서 허용되기 어려운 오류를 Human Review 전에 걸러냅니다.

📝 Generate — 문서 초안 생성
↓
🔍 Retrieve & Verify — 근거자료 재확인
↓
✅ Validate — 필수항목·불일치·출처 없는 주장 검사
↓
👤 Human Review — 전문가 최종 검토 및 승인

Human-in-the-loop

의료기기 규제 업무 특성상 AI가 최종 승인자가 되어서는 안 됩니다. 전문가 검토 프로세스는 시스템의 필수 단계입니다.

  • AI 초안 생성 → 전문가 수정 → 승인 → 최종 출력 흐름
  • AI 생성 내용과 사람이 수정한 내용을 구분하여 기록
  • 수정 이력을 통해 기업별 선호 표현·작성 방식 개선 가능
  • AI 출력의 최종 책임은 검토자(전문가)에게 있으며, 시스템은 모든 생성 근거를 추적 가능한 형태로 제공합니다

Validation 검사 항목

필수항목 누락출처 없는 주장내부자료 불일치적용 규정 누락문서 간 표현 충돌
